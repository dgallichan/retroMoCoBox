How it works

Each phase-encode line is acquired while the head sits at a different position. A rotation turns that line's sampling locations in k-space; a translation adds a linear phase ramp along it. The NUFFT simulates both exactly.

Correction uses the motion estimates (as from FatNavs): undo each line's phase ramp, then solve for the image on the rotated, non-Cartesian sampling with conjugate gradients. One iteration is a scaled adjoint (gridding) recon.

Radial uses 256 spokes of 256 samples each, so it is undersampled at the edge of k-space and shows streaks even without motion. The motion-corrupted image is the usual scanner recon that ignores motion (gridding with density compensation), and the correction adds the same density weighting to the CG.

With zero estimate error the correction uses exactly the operator that simulated the data, an "inverse crime" that flatters the result. Adding a little Gaussian error to the estimates gives a more honest picture; the faint traces on the plot show the estimates used.
